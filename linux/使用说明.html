JK808 Linux v2.3.4 双机操作说明

一台 Windows 接收电脑，通过内网 SSH 控制两台 Linux 测试主机，共用一台 8 通道 JK808。两台可以独立测试，也可以一次启动同一个流程。保留原单机入口。

v2.3.4统一所有测试图的线条、颜色及尺寸，新增可直接查看的全量SMART与JK808原始数据导出。已用离线数据与模拟设备回归；5秒SMART及双机实际硬件表现仍需现场确认。

本版更新与采样规则

v2.3.2支持128G、256G、512G、1T、2T识别及汇总。128G/256G容量页追加在原三页后，旧批次表下一次出表自动扩容，原表已有温度、图片、明细及人工内容保留。单机、双机均适用；采集周期及20点统计规则沿用上版。

先等现有任务结束，退出旧程序。完整包解压到新目录；沿用单机时复制旧config.json，已有双机配置时同时复制旧双机配置.json，保留各自真实身份。不要复制旧.venv。首次加载会备份实际配置到“配置备份”，只升级读写项，保留密码、IP、探针分配、盘身份、项目批次、L0和L1.2。公开源码不附运行环境或wheelhouse；首次部署前请按下方说明准备锁定版本的依赖。

v2.3.4 原始数据与图表

所有单机/双机的L1.2、L0、读、写共用图标准：CPU与CPU表面正红#FF0000，NAND与NAND表面亮蓝#4A91FA，环境绿#228B22，Composite紫#7209B7；全实线，无散点、无逐点数字，表面/环境线宽0.9、SMART线宽1.7。PNG固定10×6英寸、300DPI、3000×1800像素。Linux带宽保留副轴和原数据，使用灰细线。只连接真实数值，不平滑、不改值；最后真实SMART截止、起点归零、缺失断线和原选点统计规则保持。

每次报告中点“查看全部原始SMART、JK808每秒、对齐选点与统计”，或打开手工复测/原始主机数据/原始数据与选点统计.html。默认先显示全部SMART三路摄氏度，JK808逐秒表另列。原始记录、对齐选点、最大/最小/平均分区，避免把180条原始SMART误当作20个报告选点。

同目录提供SMART全部原始记录_中文.csv、JK808每秒原始记录_中文.csv、对齐选点_中文.csv、统计汇总_中文.csv。全量SMART保留所有已采原始响应、晚到和错误，以及全部已有NVMe字段；JK808保留每秒三路及八通道原字值。原始响应/报文及采样CSV在“原文件_字节保留”按字节复制并附SHA256校验。空白不补造；历史记录没有原响应时明确只导出现存采样表，无法恢复从未保存的字段。

离线复算仍只需Python标准库。随附raw_host_export.py与report_sampling.py均会复制到每次“人工复算代码”，没有tmp目录依赖。重建历史报告共用新版图标准；独立人工复算另生成“人工复算结果/原始主机数据”查看副本。查看副本写入故障会明确提示，可用已有记录离线重建，无需重新跑盘。

1. 接线与探针分配

JK808 的 REMOTE 数据口连接接收电脑。两台 Linux 与接收电脑接入可互通的内网；Linux 继续使用 SSH，不使用 Windows 项目的 FTDI 互连线。

测点主机 A主机 B
SSD 主控表面探针 1探针 4
SSD NAND 表面探针 2探针 5
本机环境温度探针 3探针 6

7、8 通道留作备用。两台环境探针分别放在各自的环境测点，避免接触发热部件。两台被测 SSD 都沿用原 Linux 程序要求：未挂载的专用 NVMe 测试盘。

2. 解压与首次启动

v2.3.4修复管理员启动闪退：入口先验证本目录和系统Python为3.12 x64，跳过商店别名及错误版本。旧.venv失效且找到可用系统Python时，先改名保留备份，再由原A部署流程重建；不删除配置和测试结果。程序退出或启动失败后窗口都会保留，启动记录在“启动记录/最近启动检查.log”和JSON中，不记录SSH密码。请勿直接双击.py文件。

  1. 将完整源码放在新目录，保留人工复算代码、requirements.lock和干净原始模板。首次使用先把config.example.json复制为config.json，再填写自己的配置；不要提交实际配置。
  2. 若要沿用旧单机的 A 机登录和仪器信息，先将旧程序的 config.json 复制到新目录。不要复制旧 .venv 或运行记录。B 机的盘身份和 TRIM 许可不会从 A 复制。
  3. 沿用原 Linux 包的环境要求：Windows 上安装 Python 3.12 x64。右键 开始测试.cmd，以管理员身份运行。
  4. 入口选择 2（一对二双机测试）。第一次会从 config.json 生成 双机配置.json，并从本目录wheelhouse离线安装依赖。公开仓库不附wheelhouse：请先在Python 3.12 x64环境执行 python -m pip download --require-hashes -r requirements.lock --dest wheelhouse，或提供同版本受信离线依赖，再运行A部署。自定义NTP会保留；默认使用ntp.aliyun.com和ntp1.aliyun.com。
  5. 进入后选 A → 3（两台）。按提示识别 JK808，确认 1～6 通道与仪器屏幕一致，然后依次填写两台 Linux 的 IP、账号、密码并确认 SSH 指纹。
  6. 程序分别查盘并填写型号、容量、序列号、固件；按提示确认各自的项目与批次。公司 NTP 默认 ntp.aliyun.com，接收电脑需要能访问它。
  7. 读写项会执行 TRIM。先核对两台专用测试盘，再在 双机配置.json → stations → A/B → ssh → allow_destructive 按实际许可设为 true。禁止给系统盘或有需保留数据的盘授权。

账号密码按之前约定明文存于本地配置。测试结果中的配置快照会清空密码。双机只编辑 双机配置.json；原 config.json 用于保留的单机入口。

3. 启动、状态与取消

入口操作
A部署或更新空闲主机的盘信息。另一台运行时可以只更新空闲的一台；此时沿用共享仪器的已核对通道，不重新打开 USB 或调整接收电脑时间。
B选择 A、B 或两台，再选 L1.2、L0→写→读，或单项 L0/写/读。核对所显示的盘身份和 BIOS 条件后启动。
C查看两台当前阶段。运行输出带“主机A/主机B”前缀。
D只取消所选主机，等待它停止本次 fio、保存记录。另一台继续。
0 / Ctrl+C取消仍在运行的两台并等待收尾后退出；请保持窗口直至收尾结束。

“两台一起启动”表示同时启动两个独立流程。各台 SSH 校时、TRIM、预写和准备耗时可能不同，不承诺 fio 在完全相同的毫秒开始。两台测次都对齐同一秒采样网格，并保留各自真实起点。

4. BIOS、换盘和继续

L1.2 完成后，程序只提示测试人员手动关闭对应的 Linux 主机并修改 BIOS。另一台不受影响。改好后在 B 选择本台的 L0→写→读即可。

L0→写→读沿用单机续测：相同主机、盘身份、项目批次和采样规则下，重新选择本台该流程，可跳过已完成项，从未完成处继续。单项测试一次只跑所选一项，不改变连跑进度。换盘后先对空闲的那台执行 A，不沿用上一块盘的写盘许可。

读、写正式采集与 fio 均为 900 秒；L0 为 1500 秒；L1.2 为 2000 秒。准备步骤、连跑间隔5分钟、SMART起始剔除、末端截尾、Excel图片自适应都沿用单机规则；读写SMART及报告按本页新版采样表执行。

6. 异常时如何处理

  • 某台 SSH、fio 或本台文件失败，仅结束该台当前流程，保留该台数据；另一台继续。某根探针无效只影响分配到该探针的指标。
  • 一台 JK808 是公共设备，拔线、仪器故障或共享原始记录无法写入可能同时影响两台；缺失按实际记录，不补零或复制上一秒温度。
  • 接收电脑仅在两台均空闲时调整系统时间。另一台运行期间，新启动任务只校准它自己的 Linux；若接收电脑与 NTP 偏差超限，新任务会停止并提示，避免改动正在采样的时间基准。
  • 更换仪器 USB 口或调整探针编号，需要两台都空闲再执行 A 重新识别。不要同时打开旧单机采集或厂家软件争用仪器。
  • 对接收电脑文件写入失败，或提示 fio 收尾失败时，保留完整任务目录及“当前状态.json”。如果进程尚未退出，不重复启动相同主机的新任务。
  • Excel 被打开占用时可能无法替换最终表。关闭 Excel 后，可用原引擎 .venv\Scripts\python.exe linux_temperature_test.py --rebuild "本次结果目录" 重新出表；两台任务都结束后再执行复算入口。

双机工作区的 A/B 运行记录分开保存，请保留它们用于续测。测试包目前没有自动推送到 GitHub。
