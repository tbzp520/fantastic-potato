JK808 + Linux v2.2.4 简洁版使用说明

本版的日常操作只有：A 首次部署，B 执行测试。全部测试代码在 linux_temperature_test.py，唯一需要修改的配置在 config.json。日期：2026-10-23。

本次新增：B → 3 单项测试，可独立选择 L1.2 / PS4、L0 / PS4、1M 写、1M 读。每次只执行所选一项，完成后返回；使用原采集、出图和批次 Excel 汇总方式。原 B → 1、B → 2 保留，单项测试不会创建或修改三项连跑的进度。

沿用 Excel 插图设置：Linux 图表插入 Excel 时铺满对应的合并单元格区域，并设置为“随单元格改变位置和大小”，取消锁定纵横比。适用于 512G、1T、2T 三页的 L1.2、L0、写、读四项图片。以后调整这些区域的行高、列宽时，图片会一起调整；独立 PNG 和 HTML 的原图不变，测试及统计规则不变。

沿用的项目归属规则：A 查盘后先确认这块盘属于哪个项目、哪个批次，再保存配置。同项目、同批次的 512G、1T、2T 共用一本温度模版.xlsx，分别填写对应容量页。项目和批次不能从硬件信息自动判断，需要测试人员明确确认。取消不保存新盘配置；同容量已有另一块盘或版本时要求另选批次。

沿用读写正式采样和 fio 各 900 秒、曲线截止到最后有效 SMART 点、B 菜单 1/2 自由选择。统计仍按正式测试最后 10 分钟，原始数据完整保留。

全新部署：先在接收电脑解压完整包到新目录，再运行“开始测试.cmd”。已有 v2.1/v2.2：等当前测试结束后按“补丁安装说明.txt”使用更新包，保留当前 config.json、公司 NTP 和结果目录。读取旧配置时会备份配置并将旧读写时长改为 900 秒。

2. 仪器和电脑怎么接

探针接在被测 SSD 的测点上；SSD 安装在 Linux 主机上。JK808 的数据线接 Windows 接收电脑，不接 Linux 主机。

按当前通道默认对应关系接线：

JK808 接口探针放在哪里程序里的名字
CH1SSD 主控表面CPU_Surface
CH2SSD 的 NAND 表面，按公司规定的测点NAND_Surface
CH3环境温度测点AMB
CH4～CH8当前不用保留原始响应，不作为启用通道检查缺失

保持热电偶正负极与仪器端子一致。仪器接好电源。REMOTE 接口用能传数据的线连到 Windows 接收电脑的 USB 口。照片里插 U 盘的接口用于存储；本程序使用的是 REMOTE 通信连接。

工位电脑通过远程桌面连接 Windows 接收电脑；接收电脑再通过内网连接 Linux。两台电脑的 IP 不要求相同网段，但必须能互通 SSH 端口。

本包沿用已在你的现场读到温度的 JK808 USB V13 格式。不要同时打开厂家采集软件和本程序去占用同一台仪器。

3. 首次准备：只做一次

Windows 接收电脑

  1. 安装 Python 3.12 x64 的 Windows 完整安装版。可用 3.12.x 补丁版本，不选 32 位、ARM64 或 embeddable zip。安装时勾选 Add python.exe to PATH，并保留 pip、venv、Python Launcher。
  2. 把本压缩包解压到一个新目录，例如 C:/JK808_v2。找到能直接看到“开始测试.cmd”和“config.json”的那层目录。
  3. 本包已经带 wheelhouse 和 requirements.lock。A 会自动安装这些依赖，不需要公司电脑访问外网下载 Python 库。
  4. 接好 JK808 数据线和公司网络。接收电脑需要能访问 NTP 校时服务器（UDP 123）；Linux 只需内网 SSH，不必联网。

Linux 测试主机

先用接收电脑上的 MobaXterm，按照平时的方法连接 Linux。已有这些工具就不用重新安装。在 Linux 命令窗口依次检查：

nvme version
fio --version
command -v setsid
python3 --version
timedatectl status

fio 应显示类似 fio-3.xx，这是磁盘测试工具。当前 Ubuntu 主机缺工具时，可由能安装软件的人员执行：

sudo apt-get install openssh-server python3 nvme-cli fio util-linux
sudo systemctl enable --now ssh

若公司 Linux 无法访问软件源，需要使用公司内网软件源或离线软件包。本压缩包中的 wheelhouse 是给 Windows Python 用的，不能拿来代替 Linux 的 fio/nvme-cli。

使用当前已有的测试账号。本流程执行原始 NVMe 命令，需要对应权限；你现场之前使用的是 root。按你的要求，A 会把登录密码明文记在本机 config.json；以后测试自动读取。交结果时取结果文件夹，里面的配置快照已去掉密码。程序目录及“配置备份”包含登录信息，不是上交资料。

4. 选 A：自动查询并填写盘信息

在 Windows 接收电脑 上操作：

  1. 右键“开始测试.cmd”，选“以管理员身份运行”。自动校准 Windows 时间时需要这项权限。
  2. 输入 A，按回车。第一次会安装离线依赖，等它结束。
  3. 如果以前用过旧版，程序会询问旧程序目录。填原来包含 config.json 的目录，例如 C:/JK808_Linux/JK808_Linux。全新部署直接回车。
  4. 输入 Linux 的 IP、登录账号和 SSH 端口。已有正确值时直接回车保留。
  5. 输入 Linux 密码。输入过程中不显示字符属于正常情况。A 全部检查成功后，密码明文保存在同一份 config.json 的 ssh.password。下次 A 若账号没有变化，回车可保留密码；更换主机或账号后重新输入。
  6. 第一次连接会显示 SSH 主机指纹，与 Linux 或已有 MobaXterm 记录核对后输入 Y。以后会记住这台主机。
  7. 程序列出未挂载的 NVMe 数据盘。只有一块候选盘时自动选择；有多块时按型号和序列号选择编号。
  8. 程序自动填写设备路径、PCI 地址、序列号、容量、型号和固件，核对 SMART 的 K/C 单位。不会自动选择正在挂载使用的系统盘。
  9. 查看本次识别的型号、序列号、容量和固件，以及原配置的盘身份。程序显示当前项目、批次和最终表格路径，询问“这块盘属于上述项目和批次吗？”：输入 Y 保留此归属；输入 N 从已有批次中选择，或填新项目和批次；输入 0 取消。回车不代表确认。
  10. 第一次没有项目或批次时，先从已有结果选择，或输入 N 填写项目和批次，再输入 Y 确认。希望跨容量汇总时，三个容量要使用相同项目名、批次名和保存总目录，不要为每个容量新建项目。
  11. 如果所选批次的同容量页已经属于另一序列号、固件或报告版本，程序会显示冲突对象，让你另选批次或取消，不覆盖原表。512G、1T、2T 各自允许不同序列号和固件。
  12. 按提示识别 JK808。需要时只拔插 REMOTE 数据线，然后核对三个温度与仪器屏幕一致，输入 Y。
  13. 看到“部署完成，登录信息和盘的项目批次归属已保存”即可。A 的检查全部通过后才保存 config.json。取消或检查失败不保存本次查盘和密码修改；旧配置读取时如触发 840 秒时长升级，该独立迁移仍会先备份并保存。

例如：项目 2380-PCBA、批次 9.24 的 512G 测完后换成 1T，再选 A，核对它确实属于 2380-PCBA / 9.24 后输入 Y。1T 的结果填入原表的 1T-温度页，512G-温度页保留；之后换 2T 同样操作。

A 是部署和检查，不执行 TRIM、不跑 fio。A 核对温度时的读数不计入正式测试数据。

换盘也可以重新选 A。新盘序列号不同时，程序会把写盘许可恢复为 false，需要你核对新盘后再开启。

5. 选 B：L1.2、三项连跑或四项单测

先完成 A，由测试人员把 BIOS 设置为所选项目需要的状态。关闭正在打开的最终温度模板，避免出表时被 Excel 占用。选 2 不要求先完成 1；选 1 也不检查后续读写的 TRIM 许可。

选 1，跑 L1.2：

  1. 输入 B，按回车，再选 1“开始 L1.2”。只有这一步会打开 config.json。
  2. 核对 A 已确认的项目、批次、保存目录、盘信息和已保存的密码。若要修改归属、报告版本或保存总目录，先保存 JSON，返回 A 重新确认后再启动测试；不能把旧盘的确认直接用于新归属。
  3. 只测 L1.2 时无需开放写盘许可。若接着要选 2，需核对可清空的专用测试盘，并在 config.json 将 allow_destructive 设为 true。
  4. 回黑窗口输入 Y。程序校时、检查盘身份，等待 30 秒，开始 L1.2。
  5. 看到“L1.2 已完成，结果已保存”后，由你手动关闭 Linux 测试主机，修改 BIOS 为后面三项的全关设置，再开机。

选 2，直接跑或继续三项：

  1. 设置好 L0、写、读所需 BIOS，等 Linux 启动、可以连接 SSH 后，选 B → 2。可以第一次就直接选 2。
  2. 这次不弹 config.json，也不重复询问已记住的密码。
  3. 程序自动执行 L0 → 等 5 分钟 → 写 → 等 5 分钟 → 读。每项仍单独生成结果，填入同一批次模板。
  4. “等 5 分钟”是两项之间新增的间隔；下一项自己的 TRIM、预写、等待步骤继续保留，详见下节。

程序不会自动关机或修改 BIOS，也不会用 bios_profile 拦截测试。人工改 BIOS 后，由 B → 2 明确开始后续三项。接收电脑的程序可以关闭再打开，运行进度会保存。

选 2 不弹配置编辑器；直接测这组时，项目和批次应已在 A 确认，请先自行打开程序目录的 config.json 核对写盘许可。三项全部完成后再次选 2 会新开一组；相同配置下中断后再选 2，会跳过已完成并保存结果的项目，重试未完成项。

选 3，独立测试任意一项：

  1. 输入 B → 3，进入“单项测试”。
  2. 选择 1=L1.2 / PS4，2=L0 / PS4，3=1M 写，4=1M 读；0 返回上一级。
  3. BIOS 按所选项目提前人工设置。只有 L1.2 会打开 config.json，保存核对后输入 Y；其余单项直接读取现有配置。
  4. 每次重新校时、核对盘身份，沿用该项原有准备步骤：L1.2/L0 等待30秒；写测试 TRIM 后等待5分钟；读测试 TRIM、预写1GiB后等待5分钟。单项不额外执行连跑的项目间等待。
  5. 读写仍要求 ssh.allow_destructive=true，且必须通过专用盘身份和未挂载检查。L0/L1.2 不依赖读写许可或其他项目的测试参数。
  6. 一项完成后返回菜单，不自动开始下一项、不自动关机。改测不同 BIOS 条件时，由测试人员手动关机、改 BIOS、开机，再选相应项目。

单测仍填入同项目、同批次的温度模版.xlsx，对应容量页的本项结果会更新，其他项目保留；每次原始测次目录独立保存。重复单测是新的一次完整测试，不会覆盖上次原始目录。

单项测试不修改“运行记录/当前流程.json”。如果之前三项连跑中断，单测之后选 B → 2 仍按原连跑进度继续；单测成功不会把连跑中的未完成项标为完成。如只想补测一个项目，使用 B → 3 即可。

输入框、结果目录和配置都仍在接收电脑上；工位电脑只需远程操作它。

JSON 位置怎么填写
company_report.project在 A 确认的项目名，例如 2380；同项目不同容量保持一致
company_report.batch在 A 确认的报告批次，例如 9.15；同项目同批次的不同容量保持一致。同容量换另一块盘或更换固件/报告版本时另选批次
company_report.output_dir保存总目录，保持 deliveries 或填空字符串 "" 即可自动保存到程序目录下的 deliveries；也可填 D:/温度数据。每次任务的子目录由程序自动创建，无需手建
company_report.capacityA 自动填入 512G、1T 或 2T，不要凭猜测修改
company_report.expected_serialA 自动填写实际盘序列号，测试前再次核对实际值
company_report.test_version首次可按固件自动填入；可填写公司完整版本名称，修改后到 A 重新确认
sample_assignmentA 自动保存盘身份和归属确认，不需要手填；归属相关字段变更后须到 A 重新确认
ssh.host / username / portLinux 的 IP、账号、端口
ssh.key_filename密码登录保持空字符串 ""。只有使用私钥文件登录才填那个文件的路径；不要填密码
ssh.known_hosts通常保持空字符串 ""；这是主机记录文件的路径，不是 Linux IP
ssh.host_keyA 自动保存的主机身份信息，保留原样，不要手填或删除
ssh.passwordA 成功后自动保存的明文登录密码。以后密码变化，重新 A 输入新密码即可；不要把此密码填到文件路径字段
ssh.password_env保持 JK500_SSH_PASSWORD；它是程序内部使用的环境变量名，不填密码
ssh.device / expected_pciA 自动查询。换盘后重新 A，不能照抄旧盘地址
ssh.allow_destructive读写测试包含 TRIM。选 2 连跑或选 3 中的读/写前核对这是可以清空的专用被测盘后，填 true；选 1 的 L1.2 不执行 TRIM，也不检查读写许可
clock_sync.ntp_servers默认 ntp.aliyun.com、ntp1.aliyun.com；若公司屏蔽公网 NTP，可填允许访问的公司 NTP 地址。旧配置没有这一节时自动使用默认值
company_report.window保持 last_600s，表示正式测试最后 10 分钟
thermometer.channel_map当前 CH1 主控、CH2 NAND、CH3 环境；测点改接其他通道时按实际修改

本版允许项目和批次使用点号、空格、括号，例如 9.15、2260-PCBA-512G、样品 A（复测）。每项不超过 60 个字符，不能以点号或空格结尾，也不能使用 Windows 保留设备名。完整路径放在 output_dir，不要把整条路径填进 project 或 batch。

密码登录时，在 ssh 里面保留以下两行（修改原行，不要另加一个 ssh 区域）：

"key_filename": "",
"known_hosts": "",

不要删掉字段，双引号中间不填空格。修改后按 Ctrl+S 保存。程序 B → 1 会显示本次实际读取的 config.json 完整路径，避免改到记事本里的另一份旧配置。

JSON 示例只是演示格式，盘信息以 A 查询结果为准：

"project": "2380",
"batch": "20260915_01",
"output_dir": "D:/温度数据"

Windows 路径建议用 /，这样不用写双反斜杠。JSON 的 true/false 不能加引号；不能写中文逗号或把末尾逗号留在右大括号前。

6. 四项测试到底怎样执行

操作阶段测试项目自动执行的顺序默认正式时长SMART 周期
B → 1L1.2 / PS4不 TRIM、不预写、不跑 fio → 等 30 秒 → 正式采样2000 秒1500 秒
B → 2 第一步L0 / PS4不 TRIM、不预写、不跑 fio → 等 30 秒 → 正式采样1500 秒60 秒
L0 结束并保存结果后，额外等 300 秒1M 写TRIM → 等 300 秒 → 正式采样并启动写900 秒60 秒
写结束并保存结果后，额外等 300 秒1M 读TRIM → 预写 1GiB → 等 300 秒 → 正式采样并启动读900 秒60 秒

例如：L0 完成 → 项目间隔 5 分钟 → 写测试校时/检查 → TRIM → 准备等待 5 分钟 → 正式写。最后一项读完成后直接提示整轮结束，不再空等。L1.2 后的人工关机、改 BIOS 时间由测试人员掌握。

TRIM 针对整块被测 NVMe 命名空间，会清除该盘已有数据。预写及正式 fio 沿用原先的 1GiB 测试范围、1MiB 块大小和队列深度 128；正式读写在该范围内循环。

旧版的 TRIM 已执行但未在黑窗口打印提示；本版会显示“开始 TRIM”“TRIM 完成”和记录位置。TRIM 命令成功返回后，程序才会继续预写或等待。可以打开本次结果目录中“手工复测/TRIM执行记录.json”，查看 command、exit_code（0 表示命令成功）、stdout 和起止时间。这里只表示设备对命令返回成功，不表示逐字节读回验证了盘内容。测试正在等待或采样时，让本次继续完成，不要为补看提示重复执行 TRIM。

TRIM、预写和等待期间不采集 JK808 或 SMART。 出现“正式测试开始，现开始采样”后，第 0 秒才开始正式记录。JK808 之后每秒一个计划采样点。

默认读写的 fio 和正式记录都为 900 秒。统计“最后 10 分钟”使用正式测试第 300～899 秒；准备等待的 300 秒不在里面。fio 真正启动时间单独保存，带宽按实际时间对齐。由于 SSH 启动有少量延迟，900 秒采样结束后最多等待 30 秒确认 fio 正常退出，这段等待不追加温度采样；超时或非零退出码仍标记未完成。

SMART 按原周期在第 0、60……840 秒采样，不在 900 秒终点额外加点。因此正常读写图统一画到原第 840 秒；若末点丢失，则截止到更早的最后有效点。截掉的原始数据仍在“手工复测”，仍按最后 10 分钟规则参与统计，不能把图的横轴长度误认为实际测试时长。

三项 60 秒 SMART 在第 0、60、120……秒采样。L1.2 默认只在第 0 和第 1500 秒采样，保持原有周期，期间不会为了检查缺失而额外频繁读取 SMART。

正式时长都放在同一个 JSON 的 tests 中。调整时需至少保留 600 秒正式记录。读写的 fio_duration_s 不得超过 duration_s。不要改 SMART 周期；本版按已确认的 60/1500 秒检查。

7. BIOS 和自动化的边界

L1.2 使用你提供照片中的开启配置；L0、写、读使用你确认的关闭 ASPM 配置。切换后启动 Linux，再运行 B → 2。

BIOS 由测试人员实际设置，程序不修改，也不再按 JSON 的 BIOS 标记拦截。 新配置不需要填写 bios_profile；旧配置有这个字段也可保留，不影响四项测试启动。读、写、L0 按你确认的全关设置；L1.2 按你给的 BIOS 照片开启相应选项。程序运行成功不能证明硬件实际进入 L1.2，工况由测试人员核对。

本版允许自由选择 1（L1.2）和 2（L0、写、读）。若需要测全部四项，可先 L1.2 → 人工关机、改 BIOS、开机 → 选 2；也可先选 2。选 2 内部仍固定为 L0 → 写 → 读。切换 BIOS 时不要有正在运行的测试。

8. 漏采和异常点怎样处理

漏采继续运行，最后告诉测试人员

JK808 每秒检查一次；SMART 只检查其应当采样的秒；带宽检查 fio 应有的一秒记录。会检查开头、结尾、中间连续丢失、单个通道无效、响应晚到和重复记录。

一次 USB/SSH 采样失败会记录原因，并在下一个计划点继续尝试。失败的 SMART 不会改成每秒重试。文件不能写入、fio 实际失败或测试人员取消，属于无法正常继续的情况，会保留已有数据并标注未完成。

没有读到的值保留为空白，不补 0、不复制上一秒、不插值。曲线在漏掉的计划点处断开；SMART 正常计划点之间的虚线仅帮助看趋势，不代表中间存在采样数据。完整性清单列出精确时间、来源和通道。一个采样点三个指标都丢失，会列三条记录。

读写测试前两个 SMART 点

只检查正式第 0 秒和第 60 秒两个计划点，分别把 Composite 与第 120 秒及以后有效 Composite 的均值比较。

  • 差值绝对值 达到 8℃：不参与统计，也不再绘图。
  • 默认 initial_smart_scope 为 round：由 Composite 判定，该轮 Composite、CPU、NAND 一起从统计和图中排除；不影响 JK808 表面温度或带宽。
  • 如果公司只想排除 Composite 自身，可将同一 JSON 中该项改为 composite。
  • 没有足够的后续有效数据时不擅自剔除，并写明无法判断。
  • 原始值在完整基础数据中保留，剔除记录说明时间、原值和原因。PNG、HTML、最终 Excel 的图都不显示已剔除值的点、连线或数值标注。
  • 有起始点剔除时，从最后一个剔除点之后的首个有效 Composite 点作为新第 0 秒。所有曲线统一截取和平移，温度和带宽仍对应同一真实时刻。例如原第 0 秒被剔除、原第 60 秒有效，则所有曲线从原第 60 秒开始，横轴统一减 60。
  • 所有曲线以最后一个有效 SMART 计划点（Composite 有效且未剔除）为共同截止点，该点之后的表面温度、环境和带宽都不画。某条线自身末端缺值时提前结束，不插值补到截止点；内部缺失保持断线。没有有效 SMART 点则图中不画曲线并明确提示；原始数据和缺失明细照常保留。
  • 图的新零点和共同截止点记在统计结果.json、复算条件和测试报告.html；原始 Second 和最后 10 分钟统计区间不变。主动剔除和漏采分别记录。
  • L0 和 L1.2 不执行这项剔除，只检查数据是否缺失。

最终统计先限定到最后 10 分钟，再使用未被排除的有效值。若前两个点本来就不在最后 10 分钟内，排除与否不会改变最终统计值。

L1.2 默认最后 10 分钟范围为第 1400～1999 秒，其中只有第 1500 秒一个 SMART 计划点。它有效时，SMART 最大、平均、最小相同是正常的；它丢失时三个统计值留空，并明确告知，不能拿第 0 秒替代。

10. 换盘、换项目和中断后继续

换盘： 等当前测试结束 → 按设备规范换盘并重新固定探针 → 配好本项 BIOS 并启动 Linux → 接收电脑选 A 更新盘身份 → 确认是否属于原项目和批次（Y 保留 / N 另选 / 0 取消）→ B 自由选 1、2 或 3。同批次换另一容量无需改批次名。选 2 前核对新盘和 TRIM 许可，新盘默认恢复 false。

换项目或批次、不换盘： 选 A 查盘，在归属提示输入 N，选择已有批次或输入新项目和批次，核对后 Y 保存。若直接在 JSON 修改这些字段，也要再 A 确认。修改保存总目录或报告版本同理；不会自动移动或合并旧结果。

同一轮 L1.2 已完成： 人工关机、改 BIOS、开机后直接 B → 2。不要再次选 B → 1；那会建立新一轮 L1.2 任务。

换 Linux 主机： A 修改 IP、账号、端口并输入对应密码，重新核对主机指纹、盘身份和探针。不要沿用另一台机器的 PCI 地址。

三项连跑中失败或按 Ctrl+C： 等当前程序收尾，保留原始资料。解决原因后再选 B → 2。已完整结束且保存结果的项目会跳过；未完整结束的那一项从头重新执行，不从中间续采。读写项重试也会重新 TRIM，已有失败测次文件夹保留。

接收电脑程序关闭后再开： 同一目录、同一 config.json 下 B → 2 会读取“运行记录/当前流程.json”。这是自动产生的进度，不是第二份配置，不需要编辑。不要删除运行记录或移动正在续测的结果目录。

项目、批次或盘变化要先在 A 确认。上述信息或采样参数变化后选 2，会建立新的三项流程，不沿用上一组的完成标记；旧进度按编号保留。密码变化不影响续跑，BIOS 字段也不会限制续跑。相同配置下中断后选 2 则续测本组，三项全部完成后再次选 2 则从 L0 新开一组。

普通缺失采样会告知并继续下一项；无法保存结果、fio 失败、人员取消等会停止后续队列。保存结果失败后可先用下节 --rebuild 重新出表；该命令不自动推进连跑进度，B → 2 仍将未登记完成的阶段作为待重试项。

11. 常见问题

为什么要求管理员运行

每次 B 选择测试后，程序先完成以下三步，再进行 TRIM、等待和正式采样：

  1. 接收电脑访问 NTP 服务器，连续读取标准时间并检查回复和延迟。默认使用阿里云公网 NTP。
  2. 把标准时间通过已核对身份的 SSH 连接写入 Linux，Linux 使用 Asia/Shanghai 时区。Linux 不需要访问互联网。
  3. Windows 也校到这个标准时间，使用 China Standard Time 时区；再对 Linux 做一次细调，检查两台电脑的时差与标准时间偏差。

右键“开始测试.cmd”选择“以管理员身份运行”；Linux 使用有校时权限的 root 账号。新功能不需要安装 Windows NTP 软件或 Linux ntpdate。这里是校准实际时钟，不是简单把显示数字加 8 小时。

校时记录保存在本次目录的 手工复测/北京时间校准记录.json，记录时间源、往返、误差估计和结果。校时成功后，结果文件夹日期按校准后的北京时间命名。CSV 原始 UTC 标记与北京时间指同一时刻；手工复测中另附 基础数据_北京时间.csv，直接按北京时间查找。

能打开网页不一定代表 NTP UDP 123 可用。如果提示联网校时失败，联系网络人员放行这两个 NTP 域名的 UDP 123，或把 config.json 的 clock_sync.ntp_servers 换成公司允许的 NTP 地址。程序不会把没有校准的旧时间标成“已对准北京时间”，也不会因此提前执行 TRIM。

老配置没有 clock_sync 时自动使用默认公网地址；旧的 auto_sync_receiver_clock 开关不再用于跳过此步骤。程序不修改现有系统 NTP 服务配置；采样中不主动改时间，若系统其他校时策略造成跳变会保留提示和原始记录。

不需要把仪器屏幕时钟改成 Linux 时间；程序按接收电脑的正式采样计划给 JK808 数据记时间。校时不能保证三台设备具有实验室级同步精度，计划时间和实际接收时间会同时留档。

连接超时

先从接收电脑用 MobaXterm 连接同一 IP、端口和账号。能登录后，再 A 核对保存信息。不要因为连接超时就改被测盘地址或反复启动 fio。

温度没有读到

关闭厂家采集程序；检查 REMOTE 数据线、供电和 USB 口。换 USB 口后重新 A 识别。测试中的短时断线会标记丢失并继续，不会自动把缺失填成看起来正常的温度。

Excel 打开着，最终模板没写进去

先关闭 Excel 中的模板和基础数据。已有原始数据不会因此删除，也不必重新 TRIM 或再测一次。

在程序文件夹的 PowerShell 窗口执行下面命令，把最后的路径换成本次结果目录：

.\.venv\Scripts\python.exe .\linux_temperature_test.py --rebuild "D:/温度数据/2380/20260915_01/512G/本次时间目录"

这条命令只重新计算、画图和填表，不连接 Linux、不采集仪器、不执行磁盘测试。若此前 fio 日志取回失败，需要先找回相应原始日志；仅重算不能补回根本未采集的数据。

最终表显示“有异常”

先看该次的“手工复测/先看数据完整性.txt”和最终模板对应的缺失明细。图可继续画、有效点仍会统计，但需要测试人员判断本次是否符合公司的上交要求。不要将缺数据的旧表当成新的完整结果。

测试流程没有封装到自定义安装库，也不依赖旧版 jk500_auto 文件夹。第三方库仅提供 SSH、USB、数据表和绘图等底层能力。CMD 只负责启动此 Python 文件。

tests/test_program.py 是离线验证用代码，不参与真实测试。维护人员可以运行：

.\.venv\Scripts\python.exe -m unittest discover -s tests -q

原版本的模板布局沿用不变；本版已完成离线流程、续跑、密码、异常数据和模板回归验证；尚未在你的现场 JK808、Linux 和被测盘上执行本次新版的完整实测。保留旧版，先在专用测试盘上验收新版流程，再用于正式批量测试。

13. v2.2.4 更新方法

现场已经用公司 NTP 跑通的设置继续保留，本次没有换成此前未交付的另一套校时方案。

  1. 先让当前测试完成并关闭程序，保留旧版和结果。
  2. 把更新包内全部文件和文件夹复制到原程序目录并覆盖同名文件，包含主程序、人工复算代码、说明和离线验证代码。更新包不含 config.json，不会覆盖公司 NTP、IP、探针、盘身份。
  3. 右键旧目录“开始测试.cmd”以管理员身份运行，确认标题为 v2.2.4。从 v2.2.2/v2.2.3 升级不需要重新部署或重新填写配置；更旧版本尚未确认盘归属时，先选 A 确认。已有 IP、密码、公司 NTP、盘信息仍保留；账号未变时密码回车保留。原配置没有归属确认记录时，B 会提示先 A，防止静默继承错误批次。
  4. 读取 config.json 时，旧读写 duration_s=840 会自动改为 900，fio_duration_s 同步为 900；已经把 duration_s 改为 900、但 fio 仍为 780 或 840 的情况也会修正。旧配置自动保存到“配置备份”，IP、密码、公司 NTP、盘信息和采样率保留。其他自定义时长不自动更改。
  5. B → 1 和 B → 2 自由选择，不需要用本版先重测 L1.2。时长变更后，选 2 从 L0 建立新组，避免沿用旧时长的完成标记。旧测次数据和模板不会因更新程序被删除。

旧的 840 秒数据也能用本版 --rebuild 重新出图，统一截止到最后有效 SMART 点；旧记录的时长和统计窗口保持原样，不会伪装成 900 秒。先复制原结果及批次模板备份，再按第 11 节命令重建，重建会更新该次报告和该批次模板对应项目。

只有 config.json 控制测试；“运行记录”和“手工复测”中的 JSON 都是自动生成的留档。完整代码包用于新部署，已有现场请优先使用更新包，保留 .venv、config.json、配置备份、历史结果。

本版没有在现场设备执行实测。离线检查覆盖四种测试的准备顺序、三项连跑顺序与等待、失败后继续、原始数据保存、人工复算、PNG/HTML/Excel 图一致性和公司模板布局。

Excel 图片自适应（v2.2.3）

四个图片区域分别是 A51:B57、A60:B66、A69:B75、A78:B84。插图以合并区域的四边为界，宽、高分别适配，不再照搬原模板旧图片的尺寸和偏移。原表的行高、列宽、合并单元格、统计数据及其他图片保持不变。

更新后新生成或重新出表的图片会使用此设置。更新程序不会自动修改磁盘上已生成的历史 Excel 文件。旧结果需要重新出表时，先关闭 Excel 并备份结果及批次汇总表，在程序目录运行以下命令，将路径换成具体一项测试的结果目录：

.\.venv\Scripts\python.exe .\linux_temperature_test.py --rebuild "D:\测试结果\具体一项测试目录"

这会用已保存的原始记录重出该项报告和 Excel，不连接仪器、不重新跑测试。其他测试的旧图片不会因此一起更新，需按项重出。
